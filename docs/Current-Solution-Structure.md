orientation. It is not exhaustive inside large component/test folders -
where a folder holds many similar files, a representative sample plus a
count is shown instead of every filename.

> Refreshed against the repository directly (file-by-file), rather than
> carried forward from an earlier draft. If you add or remove a top-level
> script, config file, workflow, or `src`/`tests`/`samples` project, please
> update this file in the same PR.

## NuGet configuration

There are three NuGet config files, each serving a different, non-overlapping
purpose:

- **`nuget.config`** - the default config picked up by any `dotnet` command
  run without `--configfile`. It defines a `local-cymrublazor-feed` source
  pointing at `./artifacts`, but that source is **disabled by default**
  (`<disabledPackageSources>`), so a plain `dotnet restore` at the repo root
  only ever hits nuget.org unless a developer explicitly re-enables it.
- **`NuGet.CI.Config`** - nuget.org only, no local feed at all. Passed
  explicitly via `--configfile NuGet.CI.Config` in `ci.yml` and
  `release.yml`, so CI and release restores can never accidentally pick up
  a locally-packed version of CymruBlazor.
- **`NuGet.Local.Config`** - defines a source (key `local`) pointing at
  `./artifacts`, distinct from `nuget.config`'s `local-cymrublazor-feed`
  key. **No script or workflow in this repository currently passes
  `--configfile NuGet.Local.Config`** - it isn't wired into any documented
  workflow. It's kept for now (see the September 2026 housekeeping pass)
  because there wasn't enough evidence to confirm it's unused rather than
  an undocumented manual-invocation convenience; if you don't rely on it
  directly, it's a candidate for removal in a future pass, superseded by
  toggling the `disabledPackageSources` entry in `nuget.config`.

The local feed itself (`./artifacts`, distinct from the git-ignored
`.artifacts/` scratch directory used by the accessibility tooling) is
populated by running `./New-LocalPackageFeed.ps1`, which packs
`src/CymruBlazor` and writes the resulting version into
`local-package-versions.props` (imported by `Directory.Packages.props`) so
`samples/*` always restore whatever was just packed, not a hand-typed
version number.
